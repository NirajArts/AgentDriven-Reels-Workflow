# Packaging and delivery

Prepare only the outputs requested: video, editable source, thumbnail/cover, title/caption, subtitles, credits and supporting files. Choose wording and aspect ratios for the user's platform. Use an actual current output for a cover where appropriate; avoid promising features or results the video does not demonstrate.

Subtitles follow reviewed audio timings and preserve exact words, except documented user-approved corrections. Record native/video/audio/caption/cover versions and hashes in the delivery manifest. Link the QA record and pending playback/listening checks.

If offering a downloadable project or repository, prepare a clean local package containing only intended files. Test a fresh extraction and the documented commands. Ensure repeated setup preserves existing work. Check for credentials, IDs, local machine paths, private media, oversized files and licensing restrictions. Never trust `.gitignore` alone to sanitize an archive.

Preparing files, publishing a repository, generating a public link, posting a video, sending messages and enabling automation are distinct actions. Record their actual status. Establish and test the delivery route before posting a CTA that promises it.
